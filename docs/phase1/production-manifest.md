## Deploy (new version)

Build once from the exact merged `main` commit in a clean checkout, through an isolated config dir so the generated `elmo.yaml` pins the final tag directly (no `latest`; production config untouched):

```bash
git worktree add --detach ../aitrckr-build <merged-sha>
SHA=$(git -C ../aitrckr-build rev-parse --short HEAD)
( cd ../aitrckr-build && node docs/phase1/ops/gen-prod-env.cjs "$USERPROFILE\\.elmo-build" g$SHA )
COMPOSE_FILE="$USERPROFILE/.elmo-build/elmo.yaml;docs/phase1/ops/prod-env.override.yaml" COMPOSE_PATH_SEPARATOR=";" COMPOSE_PROJECT_NAME=elmo-build docker compose build
```

Rehearse those exact image IDs against a restored production dump in a disposable project (own config dir, volume, loopback ports, stub provider), take a fresh verified `pg_dump -Fc`, then cut over:

```bash
cd <repo-root>
export COMPOSE_FILE="$USERPROFILE/.elmo/elmo.yaml;docs/phase1/ops/prod-env.override.yaml"
export COMPOSE_PATH_SEPARATOR=";" COMPOSE_PROJECT_NAME=elmo
node docs/phase1/ops/gen-prod-env.cjs "$USERPROFILE\\.elmo" g$SHA   # preserves keys
docker compose up -d --no-build
```

New versions go PR → CI → build → rehearsal → explicit deploy; no auto-update path exists.

## Rollback

Previous pinned images stay on disk. Regenerate the config for the prior tag and re-up — the volume is never touched:

```bash
node docs/phase1/ops/gen-prod-env.cjs "$USERPROFILE\\.elmo" g<previous-sha>
docker compose up -d --no-build
```

Never run `docker compose down -v` for project `elmo`.
