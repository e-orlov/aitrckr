## Deploy (new version)

```bash
cd <repo-root>
export COMPOSE_FILE="$USERPROFILE/.elmo/elmo.yaml;docs/phase1/ops/prod-env.override.yaml"
export COMPOSE_PATH_SEPARATOR=";" COMPOSE_PROJECT_NAME=elmo
SHA=$(git rev-parse --short HEAD)
docker compose build
docker tag elmo-web:latest elmo-web:g$SHA && docker tag elmo-worker:latest elmo-worker:g$SHA && docker tag elmo-db-migrate:latest elmo-db-migrate:g$SHA
node docs/phase1/ops/gen-prod-env.cjs "$USERPROFILE\\.elmo" g$SHA   # preserves keys
docker compose up -d --no-build
```

New versions go test stack → build → explicit deploy; no auto-update path exists.

## Rollback

Previous pinned images stay on disk. Regenerate the config for the prior tag and re-up — the volume is never touched:

```bash
node docs/phase1/ops/gen-prod-env.cjs "$USERPROFILE\\.elmo" g<previous-sha>
docker compose up -d --no-build
```

Never run `docker compose down -v` for project `elmo`.
